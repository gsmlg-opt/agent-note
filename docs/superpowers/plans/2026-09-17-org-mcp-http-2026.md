# HTTP-only MCP endpoints and 2026-07-28 implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Serve note tools at `/mcp` and Org tools at `/org/mcp`, remove the stdio MCP mode, and support the stable MCP 2026-07-28 wire protocol.

**Architecture:** Keep the existing shared pipeline contexts and MCP tool handlers. Construct two scoped `NoteMcpServer` tool routers for two stateless Streamable HTTP services; remove only the stdio transport entrypoint. Upgrade the official Rust MCP SDK to 3.4 so it supplies 2026 discovery, metadata, headers, and result serialization.

**Tech Stack:** Rust 2021, Axum, rmcp 3.4, Tokio, Cargo integration tests.

---

## File responsibilities

- `crates/note-mcp/src/stdio.rs` currently owns reusable schemas, handlers, and `NoteMcpServer`; rename it to `server.rs` while removing its stdio-only tail.
- `crates/note-mcp/src/http.rs` owns HTTP service configuration and both route mounts.
- `crates/note-mcp/src/org.rs` owns the exact 40-name Org tool router; preserve it.
- `crates/note-server/src/main.rs` owns CLI dispatch and HTTP router composition.
- `crates/note-mcp/tests/org_transports_test.rs` proves HTTP inventory, calls, and protocol behavior.
- Server integration tests prove Org transport and OpenAPI behavior.
- `crates/note-frontend/Trunk.toml`, `README.md`, and `docs/design.md` describe or proxy the endpoints.
